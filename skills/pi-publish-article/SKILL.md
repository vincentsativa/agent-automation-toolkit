## MANDATORY SEO AUTOMATION

**Every deploy MUST run `seo-maintenance.py` before building Docker.** This script:
- Auto-regenerates `sitemap.xml` with ALL articles
- Auto-regenerates `rss.xml` with ALL articles (sorted by date, newest first)
- Auto-regenerates `llms.txt` for AI crawlers
- Validates SEO (title length, meta descriptions, missing tags, etc.)
- Ensures NO articles ever get missed from sitemap

**This is the permanent fix for the weekly sitemap/RSS problems.** The script reads article metadata directly from HTML files — no manual maintenance needed.

### Step 3: Add the Article to the Homepage Data + Rebuild

The homepage is now generated from a single data file. **Do NOT edit `index.html` directly** — it is regenerated by `build-index.js`.

**3a. Prepend the new article to `articles-data.js`**

Open `~/workspace/articles/articles-data.js` and insert a new object at the **FRONT** of `window.PB_ARTICLES` (before the previous newest article). Use this exact shape:

```js
{n:109,cat:"AI Infrastructure",title:"<Title>",href:"<slug>.html",img:"images/article-109-main.jpg",date:"June 25, 2026",author:"Vinny Barreca",excerpt:"<first 1-2 sentences, ≤ ~240 chars>"},
```

Field rules:
- `n` = article number (increment the previous highest)
- `cat` = category (must match an existing category spelling exactly, e.g. `AI Infrastructure`, `AI Security`, `AI Industry`, `AI Engineering`, `AI Policy`, `AI Privacy`, `AI & Investing`, `AI & Society`, `AI Agents`, `AI Collaboration`, `AI Ethics`, `AI News`, `AI Research`, `AI Strategy`, `Cloud Infrastructure`)
- `href` = relative slug filename, e.g. `your-agent-is-a-monolith-thats-the-problem.html`
- `img` = relative path, e.g. `images/article-109-main.jpg`
- `date` = human date matching the article, e.g. `June 25, 2026`
- `excerpt` = plain text (no HTML, no quotes that break the JS string — use single quotes carefully or escape)

**Critical:** Do NOT remove or reorder any existing articles. Just add the new one at the FRONT. The featured card on the homepage is automatically the first item.

**3b. Rebuild the homepage**

```bash
cd ~/workspace/articles
node build-index.js
```

Expected output: `✅ index.html rebuilt` with the new article count and the new featured (`#109 <Title>`). This regenerates `index.html` from `index-template.html` + `articles-data.js`, emitting all article cards as static, SEO-friendly `<a>` links.

**3c. Verify locally**

Open `~/workspace/articles/index.html` in a browser (relative paths resolve to the repo, so images/scripts load). Confirm the new article appears as the featured card and as the first archive card.

### Step 7.5: Verify Social Card Image is LIVE Before Sharing (MANDATORY)

**Root cause of X/Twitter card failures:** X fetches the card the moment a link is first shared. If that happens during the deploy window (before the image/page is fully live), X caches a BROKEN card keyed by the page URL. It is very hard to fix afterward — the X Card Validator (`cards-dev.twitter.com/validator`) is now **deprecated and no longer works**. The cache-buster on the image URL does NOT help because X caches by page URL, not image URL.

**Prevention (do this BEFORE the user shares the link):**

```bash
# 1. Confirm the image is fully live and valid (200 OK, image/jpeg)
curl -sI "https://articles.phantom-byte.com/images/article-N-main.jpg?v=N" | grep -iE "HTTP|content-type"

# 2. Confirm the image is the FULL 1280x720 (16:9) original — DO NOT crop it to 1200x630
curl -s "https://articles.phantom-byte.com/images/article-N-main.jpg?v=N" -o /tmp/chk.jpg && file /tmp/chk.jpg
# Expect: 1280x720. VINNY'S PREFERENCE: keep the full 16:9 image. Do NOT re-encode/crop to 1200x630 — that cuts off the top/bottom of the image.

# 3. Confirm the page is live and all og:/twitter: tags are present
curl -s "https://articles.phantom-byte.com/<slug>.html" | grep -oE '<meta[^>]*(og:|twitter:)[^>]*>'
```

Only tell the user the article is ready to share AFTER all three pass. This prevents X from ever caching a broken card.

**Remediation (if a card is ALREADY broken):**

X caches by page URL, so re-posting the same link will keep showing the broken card. The only reliable fix is to give X a URL it has never seen:

1. **Query-string trick (works, no login):** Share the link with a fresh query string, e.g. `https://articles.phantom-byte.com/<slug>.html?x=1`. X treats it as a new URL and fetches a fresh card. The `?x=1` does not affect the page. (This is what fixed article 185.)
2. **Bump the image cache-buster** (`?v=N` → `?v=N+1`). Keep the image at the full 1280x720 (16:9) original — do NOT re-encode to 1200x630 (that crops the image). This only helps once X re-fetches the page — it does NOT force the re-fetch by itself.
3. **Do NOT rely on the Card Validator** — it is deprecated and no longer works.

- ✅ index.html updated with new article
- ✅ HSTS headers present on live site
- ✅ **Mobile scroll guard verified** — `html{overflow-x:hidden}` AND `.wrap{overflow-x:hidden}` are present in the article's inline CSS. Both are required for mobile browsers (iOS Safari ignores `body{overflow-x:hidden}` alone). Run `grep -c 'overflow-x:hidden' <slug>.html` to confirm at least 2 occurrences (html + .wrap).
- ✅ **Inside-image class verified** — if the article has an inside image, it MUST use `class="article-image article-image-right"` (floats right, max 320px on desktop). A bare `<figure class="article-image">` renders full-width and is a REJECT. Run `grep -c '<figure class="article-image article-image-right">' <slug>.html` (expect 1) and `grep -c '<figure class="article-image">' <slug>.html` (expect 0). This is the sovereign-compute regression — do not ship it again.
- ✅ **Main image is the FULL 1280x720 (16:9) original** — VINNY'S PREFERENCE. Run `file images/article-N-main.jpg` and confirm `1280x720`. **DO NOT crop/re-encode to 1200x630** — that cuts off the top/bottom of the image (this was a real miss on articles 185 & 186). Keep the full 16:9 image. If the source is already 1280x720, copy it as-is.

## ERROR HANDLING

| Error | Recovery |
|-------|----------|
| gcloud auth fails | Run `gcloud auth login`, retry |
| Build fails | Check Dockerfile, verify files exist |
| Cloud Run deploy fails | Check service exists, region correct |
| 404 after deploy | Wait 30s, hard refresh, verify filename |
| Images not loading | Check paths are `images/article-N-*.jpg` |
| SEO script fails | Run `python seo-maintenance.py --validate` to diagnose |
| Google API error | Check `google-indexing-credentials.json` or skip (site will index via sitemap) |
