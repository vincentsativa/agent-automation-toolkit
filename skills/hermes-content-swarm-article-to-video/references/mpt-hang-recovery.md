# MoneyPrinterTurbo Hang Recovery Recipe

## When to Use This

The MoneyPrinterTurbo CLI (run via `uv run python cli.py`) often hangs during the final ffmpeg video mux phase. Symptoms:
- Process has been running 5+ minutes with no new log output
- `combined-1.mp4` exists but is corrupt (`moov atom not found` when probed with ffprobe)
- No `final-*.mp4` exists in the task directory
- CPU usage has dropped to near zero

## Do Not Kill the Process Prematurely

If the CLI is still actively logging (e.g. downloading videos, generating audio, processing clips), let it finish. Only proceed with manual recovery when the process is confirmed stuck on the concat/mux step.

## Step 1: Verify the Hang

```bash
cd ~/MoneyPrinterTurbo/storage/tasks/<task-uuid>
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 combined-1.mp4
```

If it returns `moov atom not found` or similar error, the file is incomplete. Proceed to reconstruction.

## Step 2: Concatenate Temp Clips

Each task directory contains `temp-clip-1.mp4` through `temp-clip-N.mp4` plus an `ffmpeg-concat-list.txt` file referencing them.

```bash
cd ~/MoneyPrinterTurbo/storage/tasks/<task-uuid>
ffmpeg -y -f concat -safe 0 -i ffmpeg-concat-list.txt -c copy combined-raw.mp4
```

This is fast (stream copy, no re-encode) and produces a valid concatenated video.

## Step 3: Burn Subtitles and Mux Audio

```bash
cd ~/MoneyPrinterTurbo/storage/tasks/<task-uuid>
ffmpeg -y -i combined-raw.mp4 -i audio.mp3 \
  -vf "subtitles=subtitle.srt:force_style='FontName=Arial,FontSize=24,PrimaryColour=&H00FFFFFF,OutlineColour=&H00000000,Outline=2,BorderStyle=3,Alignment=2,MarginV=40'" \
  -c:v libx264 -preset fast -crf 23 \
  -c:a aac -b:a 192k \
  -shortest final.mp4
```

This produces a 1080x1920 portrait MP4 with:
- Stock footage from the temp clips
- TTS voiceover from `audio.mp3`
- Whisper-generated subtitles burned in with white text, black outline, bottom-center alignment

## Step 4: Compress for Email Delivery

A 2-minute 1080x1920 video at the above settings is typically 40-50MB. IONOS SMTP times out on uploads this large.

```bash
cd ~/MoneyPrinterTurbo/storage/tasks/<task-uuid>
ffmpeg -y -i final.mp4 -c:v libx264 -crf 28 -preset fast -c:a copy final_compressed.mp4
```

This typically halves the file size (down to ~25MB) with minimal visible quality loss. Target under 30MB for reliable SMTP delivery.

## File Inventory in Task Directory

| File | Purpose |
|------|---------|
| `audio.mp3` | TTS voiceover generated by Edge TTS |
| `subtitle.srt` | Whisper-generated timed subtitles |
| `script.json` | Parsed article text split into segments |
| `ffmpeg-concat-list.txt` | Ordered list of temp clips for concat |
| `temp-clip-*.mp4` | Individual stock footage segments (5s each) |
| `combined-raw.mp4` | Your manually concatenated output |
| `final.mp4` | Final video with audio + subtitles |
| `final_compressed.mp4` | Email-ready compressed version |

## Root Cause

The CLI uses subprocess to call ffmpeg for the final concat + audio overlay. This subprocess occasionally deadlocks or hangs indefinitely when the total clip count is high (20+ clips) and the audio track is longer than the video track. This is a known upstream issue in MoneyPrinterTurbo v1.3.0.

## Prevention

There is no reliable prevention from the agent side. The workaround is the manual reconstruction recipe above.
