# Archive Format and Parsing Recipe

Folder: `C:\Users\<user>\OneDrive\Desktop\MONEY MAKING OPPORTUNITIES\`
Plain text, `\r\n` line endings, `====` banner rules as section separators.
No markdown, no JSON.

## File types

- Daily reports: `money Making opportunity -YYYY-MM-DD.txt` (~45-65KB each,
  generated by a cron job). Seven ideas per file.
- Best-of compilations: `best-7-money-making-ideas-YYYY-MM-DD.txt` (ranked,
  scored picks distilled from earlier dailies; sometimes a `-v2` variant).
  Read these FIRST, they are the archive's own shortlist.

## Idea section shape

Each idea is a `# N. TITLE IN CAPS` heading, then usually a BLANK LINE, then
`Score: N/25 (pain x, buyer reachability y, willingness to pay z, ...)`.
Older files have no score line at all. Body fields vary by era but commonly:
PRODUCT OR SERVICE, THE PROBLEM / WHY IT MADE THE TOP 7, TARGET INDUSTRIES,
WHY THEY WOULD PAY, IMPLEMENTATION GUIDE / HOW TO GET STARTED (7-day plan),
REVENUE OPPORTUNITY / FIRST OFFER, HOW TO FIND 25-50 PROSPECTS, RISKS AND
BOUNDARIES, NEAREST PRIOR IDEA, EVIDENCE (source file it came from).
Best-of files also carry ideal buyer, starting price, and validation metric.

## Working parser (execute_code)

```python
import re, glob, os
folder = r"C:\Users\<user>\OneDrive\Desktop\MONEY MAKING OPPORTUNITIES"
ideas = []
for f in sorted(glob.glob(os.path.join(folder, "*.txt"))):
    txt = open(f, encoding="utf-8", errors="replace").read().replace("\r\n", "\n")
    parts = re.split(r"^#\s*(\d+)[.:]?\s*(.+)$", txt, flags=re.M)
    # parts = [pre, num, title, body, num, title, body, ...]
    for j in range(1, len(parts) - 2, 3):
        title, body = parts[j + 1].strip(), parts[j + 2]
        sc = re.search(r"Score:\s*(\d+)/25\s*\(([^)]*)\)", body)
        ideas.append({"file": os.path.basename(f), "title": title,
                      "score": int(sc.group(1)) if sc else None,
                      "breakdown": sc.group(2) if sc else ""})
```

Then dedupe on a normalized title prefix (first 2-3 words, e.g. `permit
clock`) keeping the max score, print a sorted title/score index, and pull the
full body only for the candidates you will actually read.

## Known parse traps

- Requiring `TITLE\nScore` matches ZERO ideas: a blank line sits between the
  heading and the score in most files. Split on the heading, search the body.
- `# 1.` numbering restarts per file, so file+title is the identity, not N.
- Scores exist only in some files (roughly half). Absence of a score is a
  property of the file's date, not the idea's quality.
- Titles drift between files for the same idea (`ADDENDA WATCH` vs
  `ADDENDUM WATCH`, `PERMIT CLEANUP` vs `PERMIT CLOSE-OUT`). Match on
  normalized prefix, not exact string.
- Some files carry a DEDUPE section listing ranked titles from prior ten
  reports, useful as an index, but it is prose, not structured data; parse
  headings instead of trusting it as complete.
